# AI Metadata System Integration Architecture

## Objective
The database and upload pipeline have been updated to support an AI-powered metadata generation system while keeping the existing normalized database design fully intact.

The system allows AI to automatically categorize, group, and tag wallpapers without affecting the offline-first experience of the application.

---

## Database Design

### 1. New AI Metadata Attributes in `wallpapers`
The following attributes describe a single wallpaper, meaning they do not share relationships across entities, and are stored directly in the `wallpapers` table:
* `style` (e.g. Anime, Realistic, Pixel Art, Minimal, Illustration)
* `primary_color` (Dominant color family, e.g. Blue, Black, White)
* `quality` (Estimated resolution/quality, e.g. HD, 4K, 8K)
* `confidence` (Double precision score representing AI's confidence in categorization)
* `indexed_at` (Timestamp when AI successfully completed generation)

### 2. Normalization Restraints
No changes were made to the relational structure. All groupings remain fully normalized:
```text
Categories
      │
      ▼
Collections
      │
      ▼
Wallpapers
      │
      ▼
Wallpaper_Tags
      │
      ▼
Tags
```

---

## AI Mapping & Tag Pipeline

### Category & Collection Resolution
The AI does not insert categories or collections. Instead, the backend supplies a list of existing categories and collections to Gemini.
1. Gemini selects matching Category and Collection names.
2. The backend queries the categories/collections tables to find corresponding IDs.
3. The mapped ID is saved as `collection_id` on the wallpaper row.

### Tag Processing
For each tag generated by Gemini:
1. The backend slugifies the tag.
2. Queries the `tags` table to check if it exists.
3. If it does not exist, it inserts the tag.
4. Inserts the relation mapping into the `wallpaper_tags` table.

---

## Offline-First Architecture

Metadata generation is performed once during upload or manual batch-indexing. Normal everyday browsing requires no internet connection.

```text
Admin Uploads Wallpaper
          │
          ▼
Image Stored (Supabase)
          │
          ▼
Gemini 2.5 Flash API (Raw Buffer)
          │
          ▼
Structured JSON Response
          │
          ▼
Backend Verification & Mapping
          │
          ├── Match Category
          ├── Match Collection
          ├── Find/Create Tags
          └── Save AI Metadata
          │
          ▼
Supabase Database Update (status = 'indexed')
          │
          ▼
Client Metadata Sync (status = 'published')
          │
          ▼
Offline Search & Browsing
```

---

## Status State Machine
- **`uploaded`**: Initial status when wallpaper record is created.
- **`pending_ai`**: Assigned when background AI analysis starts.
- **`indexed`**: AI completes processing and metadata is saved (stands in the moderation queue).
- **`published`**: Admin approves, making it available to desktop client sync runs.
